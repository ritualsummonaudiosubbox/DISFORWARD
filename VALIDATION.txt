DISFORWARD 0.6.1 - verification scope

The app uses TWO independent VB-Audio transports:
- Hi-Fi Cable: Discord receive.
- VB-CABLE: call app microphone send.
It does not create a kernel audio endpoint without the vendor driver.
SPEAKER uses a second independent engine and an explicit physical output.
The main source selection controls only the call send engine.
Dedicated Hi-Fi stream anchors negotiate both active receive engines at 48 kHz
with MATCH_FORMAT and verify GetCurrentSharedModeEnginePeriod. Persistent
endpoint formats and Windows default device choices remain unchanged.

MSVC builds use /W4 /WX. Portable tests cover audio FIFO/fades and device
pair identity, independent cable separation and container mismatch.
UI preview checks compact size, source/SPEAKER controls, Setup and PIN.
The original VB-CABLE archive checksum and kernel catalog are verified in CI.
WINDOWS-AUDIO-CHECK.txt records the actual Windows audio integration results.

No test on a remote runner can establish zero issues on every Windows PC.
Real Discord calls, physical mic/headphones, acoustic echo, customer call
software and exclusive-fullscreen behavior require a live acceptance call.
Run Check audio lines before that call. It plays short quiet generated tones;
it does not verify external application device selections.

The hosted Windows runner uses test mode. Production kernel signatures are
separately checked with SignTool /kp; Secure Boot and Memory Integrity
compatibility are not established by that runner audio test. Keep Windows
security enabled and use the original vendor installation prompts.

The DISFORWARD app/setup EXEs are not Authenticode-signed.
The vendor installers remain original. Administrator rights and a restart
may be required. No unsigned custom DISFORWARD kernel driver is installed.

0.6.1 AUDIT PATCH
- Cancelling Check audio lines preserves sending and SPEAKER state.
  Continuing explicitly stops both routes and displays muted test status.
- Receive and listening output failures identify the correct audio path.
- One setup lock covers SEND and RECEIVE, including --receive invocations.
- README.txt now matches the two-cable setup instead of the old process route.
- Windows probes also check generated audio through the microphone branch,
  microphone mute, repeated mic/friend starts and stops, and final silence.
- UI assertions check SPEAKER remains enabled through every phone source
  and Mute selection, then turns off independently.
